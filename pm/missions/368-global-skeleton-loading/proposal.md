## 전역 로딩 스켈레톤 적용

사이트의 여러 화면이 서버·API 응답을 기다리는 동안 빈 화면이거나 "불러오고 있어요…" 같은 맨텍스트만 떠서, 콘텐츠가 채워지는 순간 레이아웃이 튀었다. 이 미션은 데이터가 도착하기 전 실제 화면의 골격을 그대로 보여주는 로딩 스켈레톤을 전역에 입힌다. 특정 기능 하나가 아니라 여러 페이지에 걸친 UX·기술 개선이라 Task로 잡는다.

---

### Deliverable

- 재사용 가능한 스켈레톤 프리미티브(`frontend/src/components/Skeleton.tsx`) — 반응형·다크테마 톤·`prefers-reduced-motion` 안전.
- 공개 페이지 route-level 로딩 스켈레톤 — 프로젝트 목록/상세, 멤버, 블로그 목록/글. 실제 화면의 컨테이너 폭·헤더·카드 그리드와 정합.
- 관리자(admin) 대시보드의 맨텍스트 로딩을 화면 구조에 맞는 스켈레톤으로 교체(멤버·블로그·지원자·모집·지원서 양식·댓글·감사로그·계정·운영진).
- 결과물은 `feat-global-skeleton-loading` 브랜치의 PR로 `dev`에 들어간다.

### Why it matters

> [!IMPORTANT]
> 이 사이트의 1순위 가치는 "멋사를 5초 만에 제대로 보여주는 얼굴"이다. 로딩 중 빈 화면이나 갑작스러운 레이아웃 점프는 그 첫인상을 깎는다. 특히 기존 블로그 목록 스켈레톤은 실제 화면과 컨테이너 폭·레이아웃이 어긋나 있어(더 넓은 셸 + 없는 피처 카드), 로딩→콘텐츠 전환이 오히려 더 튀었다. 화면 골격을 그대로 예고하는 스켈레톤은 체감 속도와 안정감을 함께 올린다.

- [ ] 모바일·데스크탑 반응형에서 스켈레톤이 각 화면의 실제 배치를 따른다.

### Notes

> [!NOTE]
> 스켈레톤은 "실제 화면과 정합"이 핵심이다 — 대충 회색 박스를 뿌리면 오히려 전환이 튄다. 각 스켈레톤은 대응 화면의 컨테이너 폭·헤더·그리드 구조를 그대로 따른다.

- 무한 펄스 애니메이션은 `prefers-reduced-motion`에서 끄고 정적 자리표시만 남긴다(접근성).
- 스켈레톤은 순수 장식이라 스크린리더에서 숨기고, 로딩 상태 자체는 `role="status"`로 전한다.
- 로그인 게이트 뒤 부원(member) 대시보드는 이미 스켈레톤이 있어 이번 범위 밖. 짧게 지나가는 인증 확인 게이트("계정을 확인하고 있어요…" 류)도 그대로 둔다.
