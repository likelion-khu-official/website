# SECURITY.md — 인프라 보안 규칙

> 상위 문서: [루트 SECURITY.md](../SECURITY.md) — 공통 보안 규칙은 거기, 여긴 인프라에만 특화된 규칙.

## 이 문서는 무엇인가

인프라 작업(배포·서버·네트워크·시크릿 관리 등)에서만 적용되는 보안 규칙. 실제 서버 접근 점검과 운영 사고에서 확인된 규칙만 쌓는다.

## 언제 채워지나

- 이 도메인에서 보안 사고·취약점이 발견되고 재발 방지 규칙이 필요할 때
- 이 도메인에 특화된 보안 결정(예: GitHub Secrets 관리 방식, SSH 키·서버 접근 정책, 방화벽/포트 정책)이 내려질 때
- 에이전트가 빠지기 쉬운 이 도메인 특유의 보안 함정을 발견했을 때

항목은 **규칙 + 왜(무슨 사고/근거였는지)** 한 세트로 남긴다. 일반론 금지 — 이 프로젝트에서 실제로 있었던 것만.

## 규칙

- **공인 인바운드는 22·80·443만 연다.** 백엔드 8080·8081과 sqlite-web 8090·8091은 nginx 또는 SSH 터널 뒤에만 둔다. 앱·DB 관리 포트를 직접 공개하면 인증 표면을 우회하고 공격 면만 넓어진다(`infra/CLAUDE.md`, `docs/db-access.md`).
- **SSH `command=`에 `sqlite3` 같은 셸 실행 가능 인터프리터를 직접 걸지 않는다.** `no-pty`만으로는 `.shell`·`.system` 탈출을 막지 못했던 2026-07-04 점검 결과 때문에, DB CLI 접근은 `dbclient-sqlite-guard.sh`가 dot-command·`ATTACH`·스키마 변경을 거른 뒤에만 허용한다.
- **DB GUI는 전용 `dbtunnel` 계정의 제한된 로컬 포트포워딩으로만 연다.** 이 계정은 셸·DB 파일 권한이 없고 `permitopen`을 127.0.0.1의 sqlite-web 포트로 제한한다. 관리 편의를 이유로 nginx나 공인 포트에 sqlite-web을 노출하지 않는다.
- **실제 `.env.*`, 개인키, OCI IAM 권한 지도는 공개 레포에 두지 않는다.** 예시는 값 없는 `.example`만 추적하고, IAM 실정보는 콘솔과 비공개 인수인계 경로에서 확인한다. 이 저장소는 public이고 삭제해도 git 이력에 남기 때문이다.
