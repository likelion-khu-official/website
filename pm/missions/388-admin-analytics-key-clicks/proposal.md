# 주요 버튼과 외부 링크 클릭 수

## 문제

페이지 조회만으로는 방문자가 지원·알림·콘텐츠 탐색 같은 다음 행동을 했는지 알 수 없다. 반대로 모든 DOM 클릭을 모으면 메뉴 열기 같은 운영 가치가 낮은 잡음과 URL 토큰·입력값이 섞일 위험이 생긴다.

## 제안

- 지원하기, 모집 알림 신청, 블로그 전체 보기, 모든 프로젝트, 프로젝트 GitHub만 명시적으로 기록한다.
- 지원하기와 알림 신청은 랜딩·지원서 화면·모집 종료 안내처럼 누른 위치를 함께 구분한다.
- 서버의 고정 허용 목록에 있는 이벤트 키만 받는다. URL·버튼 문구·입력값을 이벤트 본문에 넣지 않는다.
- 클릭은 관심 신호이므로 같은 방문의 반복 클릭도 각각 센다. 지원 접수와 알림 신청 성공은 별도 실제 DB 지표로 본다.
- 선택 기간·일/주/월 간격·행동 종류에 맞춰 추이 그래프와 위치별 표를 함께 갱신한다.

## 검증

- 정해진 버튼을 여러 번 누르면 행동·위치별 수치에 정확히 반영
- 같은 지원 행동도 랜딩 모집과 지원서 화면을 분리
- 허용 목록 밖 일반 UI 클릭은 저장하지 않음
- 행동 필터를 바꾸면 URL·그래프·표·합계가 함께 갱신
- 데스크톱 hover와 390px 모바일에서 정확한 수치를 확인
