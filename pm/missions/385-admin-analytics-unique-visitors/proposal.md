# 선택 기간의 추정 순 방문자

## 문제

조회수에는 한 사람이 여러 페이지를 열거나 새로고침한 횟수가 모두 들어간다. 운영자가 실제 도달 규모를 보려면 같은 익명 방문자의 반복을 선택 기간에 한 번으로 세는 비교값이 필요하다.

## 제안

- 브라우저에서 무작위 UUID를 하나 만들고 로컬 저장공간에 보관한다. 로그인·이메일·학번·IP와 연결하지 않는다.
- 서버는 UUID 원문도 저장하지 않고 SHA-256 값만 페이지 조회 행에 남긴다.
- 선택 기간 전체에서는 같은 해시를 한 명으로, 날짜별 그래프에서는 각 날짜·주·월 안의 중복을 한 명으로 센다.
- 조회수와 추정 순 방문자를 같은 시간축의 두 직선으로 보여주고, 마우스를 올리면 ECharts 표준 축 툴팁에서 두 값을 함께 읽는다.
- 다른 기기, 브라우저 저장공간 삭제·차단은 별도 방문자로 잡히거나 순 방문자에서 빠질 수 있음을 화면에 짧게 설명한다.

## 검증

- 방문자 A가 프로젝트 2회·블로그 1회, 방문자 B가 블로그 1회 → 조회 4회·순 방문자 2명
- 전날 방문자 C를 포함하도록 기간을 넓히면 3명, 오늘로 좁히면 2명
- 프로젝트 페이지만 선택하면 A 한 명
- DB에는 64자 해시만 있고 원 UUID·IP·이메일·학번·계정 ID가 없는지 확인
