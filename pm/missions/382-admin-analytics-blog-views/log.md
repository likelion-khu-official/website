# 작업 로그

- #381은 페이지 경로만 저장하므로 slug 변경 시 과거 기록이 갈라질 수 있음을 확인했다. #382에서 콘텐츠 종류와 불변 ID를 nullable 컬럼으로 추가해 기존 일반 페이지 조회 의미는 유지한다.
- 기존 `/blog/{slug}` 조회 행을 배포 마이그레이션에서 현재 글 ID로 연결하고, 이후 조회는 수집 순간에 slug를 글 ID로 해석하도록 했다.
- 통합 테스트에서 글 A를 이전 주소로 2회, slug·제목 변경 뒤 새 주소로 1회 조회해 같은 글 ID 3회로 합쳐지는 것을 확인했다. 글을 숨긴 뒤에도 현재 제목·숨김 상태·과거 3회가 응답에 남았다.
- 글별 표와 선택 글 그래프를 데스크톱·390px에서 확인했다. 화면 캡처는 기능 패널만 잘라 리뷰어가 이전 #381 영역을 다시 훑지 않게 했다.
