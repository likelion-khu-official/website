## 동아리 공용 명의 계정
- 외부 서비스(도메인·호스팅 등) 가입의 **동아리 명의** + **후임자 인수인계용**. 개인계정 종속을 피하려 만든 것.
- 종류: 아웃룩(메일). **주소·비밀번호는 `ops.local`/비밀번호 관리자.**

## 배포 토폴로지 (CI/CD)
- **`dev` 브랜치 = stage = 테스트 환경**, **`main` 브랜치 = prod = 운영 환경.** 둘은 독립.
- **PR**이면 자동화된 테스트만, **머지 이후** 실제 배포. (동작 정리: PR #40)
- 현재 이 자동배포는 **백엔드 서버 한정.**
- 머지 정책: **일반 머지만 허용**(squash·rebase 금지 — 이유는 learnings).
- **스테이징 도메인:** `랜덤문자열.likelion-khu.com` 형태. **깃허브엔 의도적으로 비노출** → 실제 값은 `ops.local`.
  - **확인 필요(2026-07-26 발견)**: 이 설명은 예전부터 "nginx.conf에 평문 고정"이라고 적혀 있었는데, 실제 서버의 `infra/nginx.conf`를 직접 열어보니 이 nginx는 `api.prod`/`api.stage`(백엔드)만 라우팅하고 프론트 스테이징 도메인은 어디에도 안 나온다 — 프론트는 Vercel이라 이 서버 nginx가 관여할 이유가 없다. 반면 `infra/uptime-monitoring.md`는 프론트 dev/stage 모니터링 대상으로 `dev.likelion-khu.com`을 그대로 공개 문서에 적어뒀다("랜덤문자열"이 아니라 고정된 이름). 즉 "스테이징 프론트 도메인이 랜덤이고 비공개"라는 이 문서의 설명과, 실제로 공개 문서에 이미 고정 이름으로 노출된 상태가 서로 안 맞는다 — 둘 중 뭐가 최신 사실인지 장찬욱·박일하 확인 필요.

## 프론트 ↔ 백엔드 연결
- 프론트(Vercel) → `/api/*` 요청을 Next.js 서버사이드 rewrite로 백엔드(OCI)에 프록시. 브라우저는 `likelion-khu.com`으로만 요청, 백엔드 주소 비노출. CORS 불필요. (이유·패턴은 learnings)
- API prefix: 현재 `/api/...` 가정.
- 환경변수: `BACKEND_URL`(서버 전용, 브라우저 비노출).
- 계약: `shared/` (PR #41 알림 계약), 연결 적용 PR #42.

## 미결 · 리스크
- **Vercel이 프론트(박일하) 개인계정에 묶여 세팅 중.** 백엔드·도메인은 공용 명의로 가는데 프론트 배포만 개인계정 → 종속 어긋남. *공용 계정으로 옮길지 결정 필요.*
- **24h 에이전트 계획:** 동아리 공용 계정(GitHub+Claude)을 조직에 초대해 서버에 올려, 빌딩기 한정 QA/보안 에이전트로 운용 검토 중. (철학·행동 정의는 별도 스펙으로.)
