# 결과 — #338 BE · 감사로그 기록 인프라와 조회 API

> 미션이 닫힐 때 채운다. 재사용할 통찰은 pm/docs/learnings.md로 졸업.

## 산출물
- [PR #340](https://github.com/likelion-khu-official/website/pull/340) — 상태변경·관리자/멤버 인증·지원자 개인정보 열람·감사로그 열람을 `audit_events`에 기록하고, 행위자·대상·시각·행위 필터를 제공하는 읽기 전용 조회 API와 `shared/types/audit.ts` 계약을 구현했다.
- `AuditEventRepository`에는 저장·조회만 두고 앱 코드와 API에 수정·삭제 경로를 만들지 않았다. 변경 상세에는 전화번호·학번 같은 실제 개인정보 값을 넣지 않고 “변경됨” 수준만 남겼다.

## 결정
- 열람 기록은 프론트 경고와 무관하게 서버 경계에서 남긴다. API 직접 호출로 화면을 우회해도 흔적이 사라지면 안 되기 때문이다.
- 불변성의 경계는 앱 관리자까지다. SSH·DB 파일 직접 변조를 탐지하는 해시 체인은 범위 밖으로 남겼다.

## 배운 것
- 상태변경은 데이터 자체가 흔적이지만 열람은 로그가 없으면 아무 흔적도 없다. 민감 정보 시스템의 감사 범위를 정할 때 읽기 행위를 별도로 계측해야 한다.
