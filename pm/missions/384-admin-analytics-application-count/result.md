# 결과

분석 화면 맨 위에 지원 수 카드 하나를 추가했다. 모집 중에는 현재 모집, 평시에는 최근 종료 모집의 최종 접수 수와 기간을 보여주며, 아래 트래픽 조회 기간을 바꿔도 숫자가 사라지지 않는다. 새 모집을 열 때만 새 모집기 0건으로 전환된다.

## 실제 DB로 확인한 흐름

- 첫 모집 열기 → 불변 모집기 ID 생성
- 실제 지원서 2건 접수 → 첫 모집 카드 2건
- 첫 모집 닫기 → 같은 모집기 ID·종료 시각·최종 2건 유지
- 새 모집 열기 → 다른 모집기 ID·0건으로 전환
- 새 모집에 1건 접수 → 새 모집 카드 1건
- 분석 JSON에 이름·답변·지원서 양식이 포함되지 않음을 문자열 수준에서도 확인

## 배포 전 데이터 보존

- 닫힌 기존 모집과 지원서는 복구 가능한 최근 모집 하나로 묶어 평시 최종 수를 보존한다.
- 배포 시 모집이 열려 있으면 `opened_at` 전 지원서와 이후 지원서를 다른 모집기로 갈라, 과거 지원서가 현재 모집 수를 부풀리지 않는다.
- 전체 Flyway 적용 뒤 Hibernate 모델과 실제 SQLite 스키마가 일치한다.

## 화면 QA

- 데스크톱 종료 모집 카드: `evidence/desktop-closed-recruitment.png`
- 390px 모바일 종료 모집 카드: `evidence/mobile-closed-recruitment.png`
- 최근 7일 트래픽 조건과 별개로 최근 종료 모집 128건이 유지되고, 모집 기간과 카드 의미가 한 화면에서 읽힌다.
