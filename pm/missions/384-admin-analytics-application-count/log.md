# 작업 로그

- 기존 DB에는 모집 열림 상태와 전체 지원서만 있고, 지원서가 어느 모집에 속하는지는 없었다. 날짜 범위 추정은 평시 값이 흔들리므로 모집 열기 전이에 모집기 행을 만들고 접수 시 ID를 저장하도록 했다.
- 이전 데이터는 여러 과거 모집으로 정확히 나눌 근거가 없으므로 복구 가능한 최근 모집기로 묶는다. 다만 배포 시 모집이 열려 있으면 `opened_at` 전후를 갈라 이전 지원서가 현재 모집 수를 부풀리지 않게 했다. 이후 모집부터는 열기·닫기 경계가 정확히 남는다.
- 분석 응답은 모집기 시각·상태·건수만 담고 지원서의 이름·답변·스키마를 포함하지 않는다.
- 모집기 행과 싱글턴 모집 상태는 하나만 저장되고 다른 하나가 실패하면 기준이 갈라지므로, 메일 발송 트랜잭션과 분리된 짧은 전용 트랜잭션에서 두 행을 함께 열고 닫는다.
- 종료된 모집 128건을 최근 7일 트래픽 조건과 함께 렌더링해도 카드가 128건을 유지하는 것을 데스크톱·390px에서 확인했다. 안내도 평시 동작과 같도록 “새 모집이 시작될 때까지” 유지된다고 적었다.
