# 기간별 전체·페이지 조회수

## 문제

관리자는 지금 사이트가 얼마나 읽히는지, 어느 페이지가 실제로 많이 보이는지 알 수 없다. 외부 분석 서비스 화면으로 이동하면 비개발자가 계정·필터·용어를 다시 익혀야 하고, 이후 지원 수나 콘텐츠 조회수와 한 화면에서 비교하기도 어렵다.

## 조사에서 가져올 동작

- Plausible처럼 기본 기간은 최근 30일로 두고, 같은 화면에서 기간과 상위 페이지를 함께 본다.
- Grafana처럼 그래프 위 한 시점에 마우스를 올리면 날짜·조회수와 교차선을 함께 보여준다.
- Apache ECharts의 표준 `tooltip`·`dataZoom`을 사용해 툴팁과 확대 동작을 직접 발명하지 않는다.
- 그래프만으로 숫자를 읽기 어려운 관리자를 위해 같은 데이터를 정렬 가능한 표와 쉬운 설명으로도 제공한다.

## 제안

- 공개 운영 사이트의 페이지 조회만 익명으로 우리 백엔드에 저장한다. URL 쿼리, IP, 이메일, 학번, 사용자 입력값은 저장하지 않는다.
- `/admin`·`/member`·로그인/인증 경로, 개발·스테이지 호스트, 알려진 봇 요청은 서버에서 다시 걸러낸다.
- `/admin/analytics`에서 최근 7일·30일·90일과 직접 지정 기간을 선택하고, 일·주·월 단위로 조회한다.
- 전체 조회 추이는 그래프로, 페이지별 조회수는 표로 보여준다. 표에서 페이지를 선택하면 같은 그래프가 그 페이지 추이로 바뀐다.
- 기간·집계 간격·페이지 선택을 URL에 남겨 새로고침과 링크 공유 뒤에도 같은 화면을 복원한다.

## 검증

- 공개 페이지 조회 요청을 실제 HTTP로 보낸 뒤 DB 행과 관리자 집계 응답이 함께 늘어나는 통합 테스트를 둔다.
- 기간 경계, 빈 날짜 0 채움, 페이지 필터, 내부 경로·비운영 호스트·봇 제외를 자동 테스트한다.
- 데스크톱·모바일 화면과 그래프 툴팁을 브라우저에서 확인해 PR에 증거를 첨부한다.
- 데이터가 없거나 API가 실패해도 무엇을 확인하면 되는지 쉬운 문장으로 안내한다.
