# SECURITY.md — PM/운영 보안 규칙

> 상위 문서: [루트 SECURITY.md](../SECURITY.md) — 공통 보안 규칙은 거기, 여긴 PM/운영에만 특화된 규칙.

## 이 문서는 무엇인가

PM/운영 작업(`pm/` 전반 — 미션·문서·이슈 발주·콘텐츠 수급 등)에서만 적용되는 보안 규칙. 공개 협업 문서에서 실제로 확인된 개인정보·취약점 노출 함정만 쌓는다.

## 언제 채워지나

- 이 도메인에서 보안 사고·취약점이 발견되고 재발 방지 규칙이 필요할 때
- 이 도메인에 특화된 보안 결정(예: 지원자 개인정보 취급 방식, 외부 공유 문서의 정보 노출 범위)이 내려질 때
- 에이전트가 빠지기 쉬운 이 도메인 특유의 보안 함정을 발견했을 때

항목은 **규칙 + 왜(무슨 사고/근거였는지)** 한 세트로 남긴다. 일반론 금지 — 이 프로젝트에서 실제로 있었던 것만.

## 규칙

- **지원자·멤버의 실제 개인정보를 미션 박스·이슈·PR·위키·QA 증거에 복사하지 않는다.** 이름·학번·전화번호·지원 답변이 필요한 검증은 합성 데이터로 하고, 실데이터를 확인해야 하면 비공개 경로에서 최소 범위로 본 뒤 결과의 요지만 남긴다. 이 레포와 GitHub 협업 표면은 public이다.
- **미해결 보안 갭은 공개 글에 재현 절차·정확한 우회 경로를 쓰지 않는다.** 성공 기준에는 기대하는 보안 경계만, 공개 이슈에는 영향과 필요한 수정만 적고, 악용 가능한 상세는 PM·담당자에게 비공개 전달한다. 2026-07-18 QA 리뷰에서 실제 취약 경로가 공개 문서에 들어갈 뻔해 `pm/qa/GUIDE.md` 규칙으로 고정했다.
- **GitHub 이슈를 닫거나 위키에 완료로 적기 전에 대상 커밋이 `dev`에 포함됐는지 확인한다.** 보안 PR #289가 초록 체크만 받은 채 미머지·충돌 상태였는데 문서가 이미 적용 완료로 앞서가, 서버 동의 검증과 응답 통일이 없는 기간이 생겼다. 열린 PR은 증거가 아니라 후보 구현이다.
