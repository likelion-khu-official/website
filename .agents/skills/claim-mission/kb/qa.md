# Q (qa) — 부탁받은 결과를 증명한다

"빌드 됨/테스트 통과"만으로는 완료가 아니다. **처음 부탁받은 결과가 실제로 만들어졌고 걱정이 닫혔음을 근거로 보이는 것**이 완료다. 명시적인 `Done`이 있으면 각 항목도 모두 증명한다.

## 렌즈
- **부탁받은 결과별로 증거.** 무엇으로 확인했나(테스트 실행 결과·앱 실제 구동·화면·API 응답). "됐을 것"이 아니라 "이렇게 확인했다". 미션에 체크박스가 있으면 항목마다 본다.
- **실제로 굴려본다.** 코드를 읽는 것과 도는 것은 다르다. 바꾼 흐름을 실제로 실행/렌더해 관찰. (테스트·문서만 바꾼 게 아니면 반드시.)
- **미션의 경계 재확인.** 하지 말라던 것 안 했나, 다른 팀 접점 안 깼나. `Notes`가 있으면 함께 본다.
- **스코프 크리프 감사.** 부탁하지 않은 변경이 diff에 있나? 있으면 덜어내거나 IQ 게이트에서 사유를 밝힌다.
- **초보 관점 한 번.** 다음 사람이 이 변경을 5분에 이해하나(mindset).
- **검증 문서 있으면 갱신.** 이 미션이 전진시킨 기능에 `pm/qa/verification/<기능>.md`가 있으면, 이번 변경으로 시나리오 결과(pass/fail/not-run)가 바뀌었는지 확인하고 근거와 함께 갱신한다 — 지어내지 않는다, 작성 규칙은 `pm/qa/GUIDE.md`. 대상 기능이 GWT 커버 밖이면(현재 익명 방문자 관점만 커버) 해당 없음.
- **"머지 전 pass" 만료 처리.** 지금 머지하는 PR 번호가 `pm/qa/criteria/*.yaml`의 `status: pr-<이번 PR#>`에 있으면 `dev`로 바꾸고, verification에서 "PR #<이번 PR#> 코드 리뷰(머지 전)"을 근거로 pass된 항목은 `not-run`(재확인 필요)으로 되돌린다 — 머지 전 diff 리뷰는 머지 순간 근거 자격을 잃는다.

## IQ 게이트에 낼 것
처음 부탁받은 걱정이나 목표를 어떻게 닫았고 무엇으로 확인했는지, 지킨 경계와 남은 위험, 산출물 위치를 자연스럽게 설명한다. 미션에 실제 체크박스가 있을 때만 항목별 근거 표를 쓴다. 사람이 승인하면 **채간 사람이 Step 3에서 마감**한다 — `close-mission.sh`로 보드 Done + 이슈 close. (미션은 연 사람이 닫는다 — `contract.md`.)

## 함정
- 자기 코드에 관대하기 → 부탁받은 결과를 반증하려 해봐라(안 되는 케이스 먼저 쳐봐).
- 부탁받은 결과를 못 만들었는데 "대충 됨"으로 넘기기 → 되돌림(I로)이 정답.
