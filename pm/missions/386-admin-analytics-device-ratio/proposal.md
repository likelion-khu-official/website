# 모바일과 데스크톱 방문 비율

## 문제

운영자가 모바일 QA와 화면 개선 우선순위를 정하려면 선택 기간에 어떤 화면에서 조회가 발생했는지 알아야 한다. 세부 기기명은 필요 없고 개인정보·고유 기기 식별 위험만 늘린다.

## 제안

- 페이지 조회 수집 시 User-Agent를 서버 메모리에서 모바일·데스크톱·기타 셋 중 하나로 즉시 축약한다.
- DB와 분석 응답에는 분류값만 저장하고 원본 User-Agent·기기 모델·OS 버전은 남기지 않는다.
- 선택 기간의 페이지 조회 건수와 비율을 세 분류 모두 제공한다. 알 수 없는 값도 기타로 포함한다.
- 제품 분석 도구에서 익숙한 도넛 그래프와 정확한 건수·비율 표를 함께 보여준다.
- 소수 첫째 자리 비율은 최대 나머지 방식으로 배분해 세 값 합계가 항상 100.0%가 되게 한다.

## 검증

- 모바일 UA 2회·데스크톱 UA 1회·알 수 없는 UA 1회 → 50.0%·25.0%·25.0%
- 세 분류 건수 합계가 전체 4회와 일치
- 조회가 없는 기간은 세 분류 모두 0회
- 기존 조회는 삭제하지 않고 기타로 backfill
- 비로그인 사용자는 기기 분석 API에 접근 불가
