# 결과

관리자가 선택 기간의 조회수와 추정 순 방문자를 같은 그래프에서 비교할 수 있게 했다. 조회수는 반복 횟수를 포함하고, 추정 순 방문자는 같은 브라우저의 반복을 기간 전체에서 한 명으로 센다. 기간·일/주/월·선택 페이지 조건을 바꾸면 합계와 두 선이 함께 갱신된다.

## 실제 DB로 확인한 집계 규칙

- 방문자 A: 프로젝트 2회 + 블로그 1회
- 방문자 B: 블로그 1회
- 오늘 결과: 조회 4회, 추정 순 방문자 2명
- 전날 방문자 C를 포함하도록 기간 확장: 추정 순 방문자 3명
- 오늘로 기간 축소: 다시 2명
- 프로젝트 페이지만 선택: 방문자 A 한 명

## 개인정보 경계

- 브라우저는 개인·로그인과 연결되지 않은 무작위 UUID만 로컬 저장공간에 둔다.
- 서버 DB에는 UUID 원문이 아니라 도메인 구분 문자열을 포함한 SHA-256 64자만 저장한다.
- 원시 IP·이메일·학번·계정 ID는 저장하거나 분석 응답에 넣지 않는다.
- UUID 형식이 아닌 이메일 같은 값은 공개 수집 API가 400으로 거부한다.
- 다른 기기·브라우저 저장공간 삭제는 별도 방문자로 잡히고, 저장공간 차단 시 순 방문자에서 빠질 수 있어 화면에서는 계속 `추정`이라고 부른다.
- 배포 전 페이지 조회는 방문자 식별값을 임의로 만들어내지 않고 `null`로 유지한다.
