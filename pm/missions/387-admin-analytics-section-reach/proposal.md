# 랜딩 섹션별 도달 수

## 문제

랜딩이 길기 때문에 홈 방문 수만으로는 프로젝트·운영진·블로그·모집 중 실제로 어디까지 읽혔는지 알 수 없다. 섹션 전체의 50% 노출을 기준으로 삼으면 모바일의 긴 섹션은 끝까지 읽어도 기록되지 않을 수 있다.

## 제안

- 프로젝트·운영진·블로그·모집 섹션의 시작이 화면 하단 20%를 넘어 실제 콘텐츠 영역에 들어오면 도달로 기록한다.
- 같은 탭의 같은 방문에서는 섹션마다 한 번만 센다. 브라우저 세션과 DB 고유 제약 두 겹으로 빠른 스크롤·재렌더링 중복을 막는다.
- 방문 식별값은 무작위 UUID로 만들고 서버에는 단방향 해시만 저장한다. IP·계정·원본 UUID는 저장하지 않는다.
- 선택 기간의 네 섹션을 제품 분석 도구에서 익숙한 가로 막대그래프와 정확한 수치 표로 함께 보여준다.

## 검증

- 한 방문에서 프로젝트를 두 번 노출해도 1회
- 같은 방문에서 다음 운영진 섹션까지 도달하면 프로젝트 1회·운영진 1회
- 다른 방문의 프로젝트 도달은 별도 1회
- 개발 호스트와 봇 요청은 저장하지 않음
- 기간 변경 시 해당 기간의 네 섹션 집계로 갱신
- 390px 모바일과 데스크톱에서 같은 수치를 확인
