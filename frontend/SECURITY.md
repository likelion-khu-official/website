# SECURITY.md — 프론트엔드 보안 규칙

> 상위 문서: [루트 SECURITY.md](../SECURITY.md) — 공통 보안 규칙은 거기, 여긴 프론트엔드에만 특화된 규칙.

## 이 문서는 무엇인가

프론트엔드 작업(화면 구현·API 연동 등)에서만 적용되는 보안 규칙. 실제 인증·이동 경로 구현에서 확인된 함정만 쌓는다.

## 언제 채워지나

- 이 도메인에서 보안 사고·취약점이 발견되고 재발 방지 규칙이 필요할 때
- 이 도메인에 특화된 보안 결정(예: XSS/CSRF 방어, 클라이언트에 노출 가능한 값의 범위, 인증 토큰 저장 방식)이 내려질 때
- 에이전트가 빠지기 쉬운 이 도메인 특유의 보안 함정을 발견했을 때

항목은 **규칙 + 왜(무슨 사고/근거였는지)** 한 세트로 남긴다. 일반론 금지 — 이 프로젝트에서 실제로 있었던 것만.

## 규칙

- **인증 토큰을 JavaScript 저장소나 응답 바디로 옮기지 않는다.** 어드민·멤버 access/refresh 토큰은 서버가 `HttpOnly` 쿠키로만 전달한다. 프런트가 토큰을 읽어 `localStorage` 등에 저장하면 XSS가 곧 계정 탈취로 이어지고, 현재의 쿠키 경계를 무너뜨린다.
- **로그인 뒤 `returnTo`는 `/`로 시작하고 `//`로 시작하지 않는 내부 경로만 허용한다.** 외부 URL을 그대로 받으면 정상 로그인 화면이 피싱 사이트로 보내는 오픈 리다이렉트가 된다. 멤버 글쓰기 로그인 복귀 흐름(#116)에서 이 검증을 적용했다.
- **사용자 작성 Markdown에 원시 HTML 실행 경로를 열지 않는다.** 블로그 본문은 `react-markdown`과 GFM으로 렌더링하되 `rehype-raw`를 쓰지 않는다. 로그인 멤버가 쓴 글이라도 공식 공개 페이지에서 임의 스크립트·이벤트 핸들러가 실행돼서는 안 된다.
